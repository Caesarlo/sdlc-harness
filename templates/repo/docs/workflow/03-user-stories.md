# Stage 3: User Story Design

## Inputs
- Approved requirements and architecture from stages 1-2.

## What The Agent Does
- Write user stories in the form "As a <role>, I want <capability>, so that <outcome>."
- Every story must carry explicit, testable acceptance criteria — not just a narrative.
  A story without acceptance criteria cannot be broken into verifiable features later.
- Group related stories; flag any story that looks too large to fit in one feature.

## Required Output Artifacts
- `docs/product/user-stories.md`, one entry per story, each with an acceptance-criteria
  list.

## Exit Conditions
- Every story's acceptance criteria are concrete enough to become a feature's
  `verification` entry in stage 4 without rewriting.
- The user has reviewed and approved the story set.
